Page transitions use the browser's View Transitions: the effects animate snapshots, never your elements. A navigation never waits for an effect — without the API, under reduced motion with an instant effect, on a hidden page or after a failure, the update simply runs. One transition runs at a time per document. Use `usePageTransition()` in React or `startPageTransition()` anywhere; with the second, wrap React updates in `flushSync`.

## PT01 · Cross-fade [#pt01]

The default effect of `startPageTransition`, `"fade"`, cross-fades the old and the new content. Pass `scope` to limit it to the part that changes; the default is the whole document.

<Effect id="PT01" />

## PT02 · Shared element [#pt02]

`<SharedElement>` morphs two elements with the same `name` across an update: size and position are animated by the browser. Names must be unique on the page at each moment; a duplicate is skipped with a development warning.

<Effect id="PT02" />

## PT03 · Slide [#pt03]

`effect: "slide"` of `startPageTransition` pushes the pages in the given `direction`. Under reduced motion it becomes a short fade, without travel.

<Effect id="PT03" />

## PT04 · Navigation direction [#pt04]

`useNavigationDirection` reports `forward`, `back`, `replace` or `unknown` from the Navigation API entry indexes; URLs are never compared. `trackNavigationDirection` is the engine, and `direction: "auto"` uses its value.

<Effect id="PT04" />

## PT05 · Scale-through [#pt05]

`effect: "scale"` of `startPageTransition` moves through the old page into the new one. It suits drill-down navigation; under reduced motion it fades.

<Effect id="PT05" />

## PT06 · Curtain wipe [#pt06]

`effect: "wipe"` of `startPageTransition` uncovers the new page with a moving edge that follows `direction`. Under reduced motion the update is immediate.

<Effect id="PT06" />

## PT07 · Route progress [#pt07]

`<RouteProgress>` shows an indeterminate `role="progressbar"` while `pending`, after `delay` (120 ms) so that fast navigations never flash, and never invents a percentage. `failed` shows the error state and `announce` adds a status message.

<Effect id="PT07" />

## PT08 · Persistent element [#pt08]

`<PersistentElement>` keeps an element that stays mounted, such as a player, still above the changing page. It is the same DOM node, so its state survives by itself.

<Effect id="PT08" />

## PT09 · Cross-document transitions [#pt09]

Import the MPA stylesheet in both same-origin documents and the browser animates full page loads; `enableCrossDocumentTransitions` optionally adds the effect and direction. Firefox 159 navigates normally. There is no live example here because it needs two documents; the Playground has one.

<Effect id="PT09" />

## PT10 · Router adapters [#pt10]

`<NextPageTransitions>` and `<TransitionLink>` connect the Next.js App Router (16.4 or later) with progress, direction and focus after a commit; `page-transitions/react-router` does the same for React Router 8. Both are optional peers and never prevent defaults.
