## Purpose

`DropdownMenu` shows a list of **commands** from a trigger: account menus, row actions, toolbar
overflow. It uses menu semantics (`menu`, `menuitem`, `menuitemcheckbox`, `menuitemradio`).

## Import

```tsx title="import.tsx"
import {
  DropdownMenu,
  DropdownMenuContent,
  DropdownMenuItem,
  DropdownMenuTrigger,
} from "@neshel-ui/components";
```

- Run commands in `onSelect` (keyboard and pointer). The menu closes after a selection; call
  `event.preventDefault()` in `onSelect` to keep it open.
- `DropdownMenuItem variant="destructive"` styles dangerous commands.
- `DropdownMenuShortcut` only **displays** a shortcut; register the key binding yourself.

## Controlled and uncontrolled

Menu: `open` / `defaultOpen` / `onOpenChange`. Checkbox items: `checked` / `onCheckedChange`. Radio
groups: `value` / `onValueChange`.

## Accessibility

Focus moves into the menu on open and returns to the trigger on close. Items are announced with their
role and checked state. Labels (`DropdownMenuLabel`) and separators structure long menus.

## Keyboard

| Key                 | Action                                  |
| ------------------- | --------------------------------------- |
| Enter / Space / ↓   | Open from the trigger                   |
| ↓ / ↑, Home / End   | Move between items                      |
| Type letters        | Jump to a matching item                 |
| → / ←               | Open / close a submenu                  |
| Enter / Space       | Activate the item                       |
| Escape              | Close the menu (innermost first)        |

## Common mistakes

- Navigation links in a DropdownMenu: users of screen readers expect commands. Use a
  [NavigationMenu](/en/docs/components/navigation-menu/) or plain links.
- Using `onClick` instead of `onSelect` — keyboard activation would be missed.
