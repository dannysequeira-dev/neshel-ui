## Purpose

`Switch` turns a setting on or off. Use it for immediate, binary settings; use a checkbox for
choices confirmed with a submit button in long forms.

## Import


## Controlled and uncontrolled

`checked` with `onCheckedChange`, or `defaultChecked`. In a form the switch submits `name=value`
(`value` defaults to `"on"`) only while it is on; `required` blocks submission while it is off;
a form reset restores `defaultChecked` and, like native inputs, does not call `onCheckedChange`.

## Sizes and states

`uiSize` is `sm`, `md` (default) or `lg`, like the other fields. `readOnly` keeps the value and stays
focusable; `disabled` removes it from the tab order and from the form data.

## Accessibility

- A native `<button role="switch">` with `aria-checked`; associate a `<Label htmlFor>` with its
  `id` (clicking the label toggles it).
- `invalid` sets `aria-invalid`; describe the error with `aria-describedby`.
- Visible focus ring on keyboard focus, system colours in forced-colours mode, no thumb transition
  under reduced motion.

## Keyboard

| Key           | Action          |
| ------------- | --------------- |
| Space / Enter | Toggle          |
| Tab           | Move focus      |

## Common mistakes

- A switch without a label, or a label that changes with the state: keep the name constant and let
  `aria-checked` tell the state.
- A switch that only takes effect after pressing Save: use a checkbox.
- Reading `false` from the form data: an off switch is absent, like an unchecked checkbox.
