Peers: `react` and `react-dom` 19, `@neshel-ui/config` (types). No Tailwind, `@source` or provider is
required. Interactive parts use Radix (dialogs, sheets, popovers, menus, navigation menu, tooltips)
and Base UI (Select, MultiSelect, Combobox) internally; you only use Neshel's API.

## Conventions

- **Flat names**: `DialogContent`, `NavbarBrand` (no `Dialog.Content`), so client references work in
  React Server Components.
- **`asChild`**: render your element (links, router links) with the component's styles and behaviour —
  exactly one element child; classes join, styles merge, handlers compose (child first), refs compose.
- **State**: stateful components offer `value` / `defaultValue` / `onValueChange` (or `open` /
  `defaultOpen` / `onOpenChange`).
- **Portals**: overlay contents accept `container`; themes are copied across portals.
- **Responsive props**: Button `size`, AppShell `breakpoint`, NavbarNav `hideBelow`, MobileMenu
  `breakpoint` accept your configured breakpoint names.
- **Icons**: bring your own React nodes (the examples use `lucide-react`). Icon-only buttons need an
  `aria-label`.

## Errors

Invalid usage throws `NeshelComponentsError` during render on the server and the client, with a
message naming the component and the fix (for example `<Button asChild disabled>` — links cannot be
disabled).

```tsx title="error-boundary-check.tsx"
import { NeshelComponentsError } from "@neshel-ui/components";

export function describeError(error: unknown): string {
  return error instanceof NeshelComponentsError ? `Neshel usage error: ${error.message}` : String(error);
}
```

## Styling

Component rules live in the `components.neshel` cascade layer and read only semantic tokens. Override
with tokens (preferred), component custom properties, Tailwind utilities or your own CSS through
`className`. See [Theming](/en/docs/guides/theming/#component-level-custom-properties).
