## Purpose

`AlertDialog` interrupts the user to confirm an important, usually destructive, action. Unlike a
Dialog it cannot be dismissed by pressing outside.

## Import

```tsx title="import.tsx"
import {
  AlertDialog,
  AlertDialogAction,
  AlertDialogCancel,
  AlertDialogContent,
  AlertDialogDescription,
  AlertDialogFooter,
  AlertDialogHeader,
  AlertDialogTitle,
  AlertDialogTrigger,
```

`AlertDialogAction` and `AlertDialogCancel` take Button `variant` and `size` (Action defaults to
`primary`, Cancel to `outline`) and support `asChild`. Both close the dialog; run your action in
Action's `onClick`.

## Controlled and uncontrolled

Like Dialog: `open`, `defaultOpen`, `onOpenChange`. For an asynchronous action, control `open`,
render a regular `Button` (with `loading`) instead of `AlertDialogAction`, and close the dialog
yourself when the action completes.

## Accessibility

- Role `alertdialog`, named by the title and described by the description (both required).
- **Cancel receives initial focus**, so an accidental Enter does not confirm.
- Escape cancels; outside presses are ignored.

## Keyboard

| Key             | Action                         |
| --------------- | ------------------------------ |
| Tab / Shift+Tab | Move between Cancel and Action |
| Enter / Space   | Activate the focused button    |
| Escape          | Cancel                         |

## Common mistakes

- Using AlertDialog for information that needs no decision — use a Dialog or inline message.
- Labels like "Yes"/"No": name the action ("Delete project").
