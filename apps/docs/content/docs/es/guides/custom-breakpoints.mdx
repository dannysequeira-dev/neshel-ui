---
title: Breakpoints personalizados
description: Define tus propios breakpoints (phone … wide), genera CSS y declaraciones TypeScript y mantén Tailwind sincronizado.
---

Las props adaptables usan por defecto los breakpoints de Tailwind v4 (`sm` 40rem, `md` 48rem, `lg`
64rem, `xl` 80rem, `2xl` 96rem). Una aplicación puede sustituirlos o ampliarlos en
`neshel.config.ts`. La CLI genera entonces el CSS para esos breakpoints y las declaraciones
TypeScript que hacen que los nombres pasen la comprobación de tipos. Nada relacionado con los
breakpoints se evalúa en el navegador.

## Ejemplo completo: phone … wide

### 1. Configurar

```ts title="neshel.config.ts"
import { defineConfig } from "@neshel-ui/config";

export default defineConfig({
  breakpoints: {
    mode: "replace",
    values: {
      phone: "30rem",
      phoneXL: "40rem",
      tablet: "48rem",
      laptop: "64rem",
      desktop: "80rem",
      wide: "96rem",
    },
    tailwind: true,
  },
  output: "./src/neshel.generated.css",
  types: "./src/neshel.generated.d.ts",
});
```

### 2. Generar

```bash
pnpm exec neshel generate
# neshel: wrote src/neshel.generated.css (2 themes, 6 breakpoints, layout + typography + components, 0 warnings).
# neshel: wrote src/neshel.generated.d.ts.
```

La hoja incluye las reglas completas de layout, tipografía y componentes para **tus** breakpoints
(para cada paquete instalado junto a la CLI), los tokens y, con `tailwind: true`, un bloque `@theme` de
Tailwind:

```css title="src/neshel.generated.css (extractos)"
@layer components.neshel {
  :root { --neshel-breakpoints: "phone phoneXL tablet laptop desktop wide"; }
  @media (min-width: 48rem) {
    .neshel-tablet-gap-4 { gap: calc(var(--neshel-spacing) * 4); }
  }
}

@theme {
  --breakpoint-*: initial;
  --breakpoint-phone: 30rem;
  --breakpoint-phoneXL: 40rem;
  --breakpoint-tablet: 48rem;
  --breakpoint-laptop: 64rem;
  --breakpoint-desktop: 80rem;
  --breakpoint-wide: 96rem;
}
```

```ts title="src/neshel.generated.d.ts" no-check="archivo de declaraciones generado, mostrado tal cual; amplía el módulo para todo el programa"
// Generated by "neshel generate" from neshel.config.ts; do not edit.
export {};

declare module "@neshel-ui/config" {
  interface BreakpointRegistry {
    readonly names: "phone" | "phoneXL" | "tablet" | "laptop" | "desktop" | "wide";
  }
}
```

### 3. Conectarlo

- Añade `src/neshel.generated.d.ts` a `tsconfig.json` (`include`). Funciona con la resolución
  `Bundler` y `NodeNext`.
- Importa la hoja generada **después** de las hojas de los paquetes (o en su lugar):

```css title="src/index.css"
@import "tailwindcss";
@import "@neshel-ui/config/tailwind.css";
@import "@neshel-ui/layout/styles.css";
@import "@neshel-ui/typography/styles.css";
@import "@neshel-ui/components/styles.css";
@import "./neshel.generated.css";
```

### 4. Usar los nombres

```tsx title="src/Products.tsx" no-check="usa los nombres de breakpoint personalizados, que requieren las declaraciones generadas; lo verifica pnpm check:next"
import { Button } from "@neshel-ui/components";
import { Grid, Stack } from "@neshel-ui/layout";
import { Heading } from "@neshel-ui/typography";

export function Products() {
  return (
    <Stack space={{ base: "4", tablet: "8" }}>
      <Heading size={{ base: "xl", laptop: "3xl", wide: "5xl" }}>Products</Heading>
      <Grid columns={{ base: 1, phoneXL: 2, laptop: 3, wide: 4 }} space="4">
        <Button size={{ base: "sm", tablet: "md" }}>Add product</Button>
      </Grid>
    </Stack>
  );
}
```

Con `replace`, `md` pasa a ser un error de tipos, y utilidades de Tailwind como `tablet:flex` cambian
exactamente en los mismos anchos que las props.

## `extend` frente a `replace`

| Modo      | Nombres disponibles                      | Úsalo cuando                                         |
| --------- | ---------------------------------------- | ---------------------------------------------------- |
| `extend`  | `sm md lg xl 2xl` **más** tus nombres     | Quieres uno o dos umbrales adicionales               |
| `replace` | solo tus nombres                          | Tu sistema de diseño tiene su propia escala          |

`extend` no puede redefinir un nombre predeterminado y todos los anchos deben ser distintos, así que
`phoneXL: "40rem"` (igual a `sm`) solo funciona en modo `replace`. Ejemplo de `extend`:

```ts title="neshel.config.ts"
import { defineConfig } from "@neshel-ui/config";

export default defineConfig({
  breakpoints: { mode: "extend", values: { phone: "30rem", tablet: "52rem" } },
});
```

## Reglas

- Nombres: lower camelCase (`phoneXL`), únicos sin distinguir mayúsculas, no reservados (`base`,
  prefijos de clase de Neshel, nombres de variante de Tailwind como `dark` o `print`). Como máximo 12
  breakpoints.
- Anchos: solo `rem`, distintos. La salida siempre se ordena por ancho.
- `base` es opcional en cualquier objeto adaptable: por debajo de la primera clave escrita la
  propiedad simplemente no se establece (se aplica el valor predeterminado del componente).

## Herencia adaptable y valores estáticos

```tsx fragment
<Stack space="4">
  <Grid columns={{ base: 1, md: 3 }} space={{ md: "6" }}>
    <Box>Static spacing on the Stack; responsive columns and spacing on the Grid.</Box>
  </Grid>
</Stack>
```

- Un valor simple (`space="4"`) se aplica en todos los anchos.
- Un objeto se hereda hacia arriba: `{ base: 1, md: 3 }` es 1 hasta `md` y luego 3, también en `lg`,
  `xl` y `2xl`.
- `{ md: "6" }` sin `base`: sin espacio por debajo de `md`.

## Nombres de breakpoint no admitidos

El código en ejecución no tiene configuración, así que no puede conocer tus nombres. Las claves mal
formadas (`{ "Tablet!": … }`) lanzan un error. Una clave bien formada pero desconocida
(`{ tablett: … }`) no se puede rechazar en ejecución: TypeScript la rechaza cuando se incluyen las
declaraciones generadas y, en el navegador, Neshel muestra **un aviso por cada clave desconocida**
comparándola con `--neshel-breakpoints` de la hoja cargada. El renderizado en servidor nunca avisa y
el marcado nunca depende de la configuración.

## Tailwind CSS v4 y CSS plano

- Con Tailwind: establece `tailwind: true` e importa el archivo generado desde tu CSS de entrada de
  Tailwind. `replace` borra primero los breakpoints predeterminados de Tailwind
  (`--breakpoint-*: initial`).
- Sin Tailwind: deja `tailwind` sin definir. El archivo generado es entonces CSS plano que puede
  cargar cualquier empaquetador (o ninguno).

## Cómo se propagan los cambios

```text
neshel.config.ts ──neshel generate──▶ neshel.generated.css   (tokens + reglas de paquetes + @theme)
                                  └─▶ neshel.generated.d.ts  (ampliación de BreakpointRegistry)
```

Edita la configuración → ejecuta `neshel generate` (lo hacen tus scripts `dev`/`build`) → el
empaquetador recoge el nuevo CSS y TypeScript ve los nuevos nombres. En CI, `neshel generate --check`
falla cuando cualquiera de los dos archivos está desactualizado. Un resultado sin cambios nunca se
reescribe, así que los vigilantes de archivos no entran en bucle.
