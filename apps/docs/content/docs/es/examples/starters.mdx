Hay tres proyectos de inicio en el directorio [`starters/`](https://github.com/dannysequeira-dev/neshel-ui/tree/main/starters)
del repositorio. Cada uno es una aplicación completa con configuración real —sin alias del monorepo—
que instala `@neshel-ui/*@^0.1.0` desde npm. El CI de Neshel-UI los compila a partir de los paquetes
empaquetados (`pnpm check:starters`), y los paquetes 0.1.0 publicados se verificaron instalando cada
ZIP desde el registro de npm y compilándolo (`pnpm check:starters --from-registry`).

| Proyecto         | Tecnología                                          | Muestra                                            |
| ---------------- | --------------------------------------------------- | -------------------------------------------------- |
| `vite-tailwind`  | React 19, Vite 8, Tailwind CSS v4, TypeScript       | Integración con Tailwind, componentes, cambio de tema |
| `vite-css`       | React 19, Vite 8, CSS plano, TypeScript             | Sin Tailwind en absoluto                           |
| `next-app`       | Next.js 16 App Router, Tailwind CSS v4, TypeScript  | Server Components, breakpoints y tema propios      |

## Descargar

<StarterDownloads />

Descomprime el archivo, instala las dependencias y arráncalo:

```bash
cd vite-tailwind
pnpm install
pnpm dev
```

También funcionan npm (`npm install`, `npm run dev`) y Yarn. Los archivos no incluyen archivo de
bloqueo, así que la primera instalación resuelve las últimas versiones compatibles.

## Copiar desde el repositorio

También puedes copiar el directorio de un proyecto desde un clon del repositorio:

```bash
git clone --depth 1 https://github.com/dannysequeira-dev/neshel-ui.git
cp -r neshel-ui/starters/vite-tailwind my-app
cd my-app
```

En Windows PowerShell usa `Copy-Item -Recurse neshel-ui/starters/vite-tailwind my-app`.

Después ejecuta `pnpm install` y `pnpm dev` en `my-app`.

### Con cambios aún no publicados

Para probar un proyecto con el código actual del repositorio, todavía sin publicar, compila y
empaqueta los paquetes en el clon y apunta el proyecto a los tarballs:

```bash
cd neshel-ui
pnpm install --frozen-lockfile
pnpm build:packages
node scripts/pack-local.mjs --out ../neshel-tarballs
cd ../my-app
node ../neshel-ui/scripts/pack-local.mjs --use ../neshel-tarballs
pnpm install
```

`--use` reescribe las dependencias `@neshel-ui/*` del proyecto con rutas `file:` a los tarballs.
