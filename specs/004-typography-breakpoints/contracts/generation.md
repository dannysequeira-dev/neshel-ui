# Contract — `neshel generate` (feature 004 additions)

Extends [feature 002 contracts/cli.md](../../002-config-and-tokens/contracts/cli.md). Everything
not mentioned here (discovery, loading, exit codes, path safety, atomic writes) is unchanged.

## Command line

```text
neshel generate [--config <path>] [--out <path>] [--types <path>] [--check] [--strict] [--debug]
```

`--types <path>` (cwd-relative, must end in `.d.ts`) overrides the config `types` key. `validate`
rejects `--types` like `--out`.

## Outputs

| Output       | Written when                | Path                                                                |
| ------------ | --------------------------- | ------------------------------------------------------------------- |
| Stylesheet   | always                      | `--out` › config `output` › `./neshel.generated.css` (config dir)   |
| Declarations | `breakpoints` is configured | `--types` › config `types` › `./neshel.generated.d.ts` (config dir) |

- Both are validated before anything is written; on an error nothing is written.
- Each is written atomically and only when its bytes differ (`unchanged` otherwise).
- When `breakpoints` is not configured and a file exists at the declarations path whose first line
  is the Neshel header, `generate` removes it and `--check` reports it as stale. A file without
  the header is never touched.
- `--check` compares both outputs and exits 4 if any is missing or stale (naming each file);
  otherwise 0. It never writes or removes.

## Stylesheet structure (in order)

1. `/* Generated by "neshel generate" from <config basename> (config schema 1); do not edit. */`
2. `@layer neshel.defaults, neshel.config;`
3. `@layer neshel.config { … }` — tokens, including the font metric custom properties
   ([typography-css.md](typography-css.md) §1).
4. Capsize fallback `@font-face` rules, one per configured fallback, in role order
   (`body`, `display`, `mono`) then list order. Omitted without fallbacks.
5. When `breakpoints` is configured, for each installed component package in the order
   `@neshel-ui/layout`, `@neshel-ui/typography`:
   `/* <package> <version> component styles (breakpoints: <names>) */` followed by the rendered
   component stylesheet (§ Rendering). Missing packages are skipped; if none is found the CLI
   warns `no-component-packages` (declarations and Tailwind output are still generated).
6. When `breakpoints.tailwind` is `true`: the `@theme` block of
   [breakpoints.md](breakpoints.md) §6.

Without `breakpoints`, sections 5–6 are absent, so feature 002 output changes only by the metric
custom properties (section 3).

## Style manifests

Each React package exports `./style-manifest.json` (schema 1), generated from its TypeScript
tables:

```json
{
  "schema": 1,
  "package": "@neshel-ui/layout",
  "version": "0.0.0",
  "layer": "components.neshel",
  "rules": [{ "selector": ".neshel-stack", "declarations": [["display", "flex"]] }],
  "responsive": [{ "class": "gap-4", "declarations": [["gap", "calc(var(--neshel-spacing) * 4)"]] }]
}
```

- `rules`: non-responsive rules in source order (selectors may contain pseudo-elements).
- `responsive`: class suffixes (`<key>-<token>`, characters `[A-Za-z0-9._-]`) and declarations.
- The CLI resolves `<package>/style-manifest.json` from the configuration file's directory
  (Node resolution with `exports`). A manifest with another `schema`, a mismatching `package`, or
  strings containing `{`, `}`, `;` (selectors/values) or `*/` is rejected with exit code 5
  (`incompatible-manifest`), naming the package.

## Rendering (shared by package builds and the CLI)

```css
@layer components.neshel {
  :root { --neshel-breakpoints: "<names ascending, space separated>"; }
  <rules, one per line: selector { prop: value; … }>

  <responsive rules at base: .neshel-<class> { … }>

  @media (min-width: <width>) {
    <responsive rules: .neshel-<bp>-<class> { … }>
  }
  … one block per breakpoint, ascending width
}
```

- Class names escape `.` (`neshel-gap-0\.5`); breakpoint names are emitted verbatim (grammar
  guarantees safe identifiers).
- LF line endings, two-space indentation, trailing newline; byte-identical on every OS.
- The package `styles.css` files are this function's output for the default breakpoints and are
  committed; drift tests compare them with the renderer and the manifests.

## Declarations

See [breakpoints.md](breakpoints.md) §4. Names in ascending width order; LF; trailing newline.

## Diagnostics added

`invalid-breakpoint-name`, `reserved-breakpoint-name`, `duplicate-breakpoint-name`,
`breakpoint-redefined`, `invalid-breakpoint-width`, `duplicate-breakpoint-width`,
`too-many-breakpoints`, `empty-breakpoints`, `breakpoint-order` (warning), `invalid-types-output`,
`invalid-metrics`, `missing-metrics` (warning), `invalid-fallbacks`, `no-component-packages`
(warning). The feature 002 `reserved` info for `typography.metrics` is removed (metrics now produce
CSS).

## Consumer scripts (documented, not automated)

```json
    "build": "neshel generate && tsc --noEmit && vite build",
    "check:neshel": "neshel generate --check"
  }
}
```
