# Contract — `neshel` CLI (proposed)

Status: **proposed**, not implemented. Recorded as ADR 0007 (Proposed).
Package: `@neshel-ui/cli`, Node `>=22.13`, ESM, executable `neshel`.
Runtime dependencies: `@neshel-ui/config` (engine) and `jiti` (⚑ Q4). Argument parsing uses
`node:util` `parseArgs`; no other dependency.

## Commands

```text
neshel validate [--config <path>] [--strict] [--debug]
neshel generate [--config <path>] [--out <path>] [--check] [--strict] [--debug]
neshel --help | -h
neshel --version | -v
```

| Option            | Meaning                                                                  |
| ----------------- | ------------------------------------------------------------------------ |
| `--config <path>` | Use this file instead of discovery. Relative to the working directory.   |
| `--out <path>`    | Overrides `output` from the config. Relative to the working directory.   |
| `--check`         | Generate in memory, compare with the existing file, never write. For CI. |
| `--strict`        | Contrast warnings become errors (same as `contrast: "error"`).           |
| `--debug`         | Print stack traces for load/internal failures.                           |

Not in feature 002: `init`, `--watch`, JSON output, programmatic API from `@neshel-ui/cli`
(its `.` entry stays empty and side-effect free).

## Discovery

- Look in the **current working directory only** (no upward search) for, in order:
  `neshel.config.ts`, `neshel.config.mts`, `neshel.config.js`, `neshel.config.mjs`.
- More than one match → ambiguity error (exit 3) listing them.
- `.cts`/`.cjs` are not supported (ESM-only).
- `--config` bypasses discovery; the file must exist and use a supported extension.

## Loading

- `jiti` loads the file (transpiling TS in memory, no files written), with the config's own
  directory as base so relative imports and `@neshel-ui/config` resolve from the consumer's
  project.
- The default export must be an object (as returned by `defineConfig`). Functions, promises
  and missing default exports are load errors.
- Loading executes the consumer's code with their privileges (same trust model as
  `vite.config.ts`). The CLI never loads configs from URLs or from `node_modules`.

## Output

- Path: `--out` › config `output` (relative to the config file) › `./neshel.generated.css`
  next to the config.
- Refused: paths inside `node_modules`, the config file itself, non-`.css` extensions (exit 2).
- Parent directories are created. Writes go to a temporary sibling file then `rename`
  (atomic on all three OSes for same-volume renames).
- If the content is byte-identical, the file is not touched.
- Content: header comment `/* Generated by @neshel-ui/cli <version> from neshel.config.ts — do not edit. */`
  (file **name** only, never an absolute path; no timestamps), LF, trailing newline.

## Exit codes

| Code | Meaning                                                                           |
| ---- | --------------------------------------------------------------------------------- |
| 0    | Success (warnings may be printed)                                                 |
| 1    | Validation failed (schema errors, or contrast errors under strict/`"error"` mode) |
| 2    | Usage error: unknown command/option, invalid `--out`, missing option value        |
| 3    | Config not found, ambiguous, failed to load, or default export not an object      |
| 4    | `generate --check`: output missing or out of date                                 |
| 5    | I/O or unexpected internal error (stack trace with `--debug`)                     |

## Human-readable output

```text
$ neshel generate
neshel: loaded neshel.config.ts
warning themes.sepia   contrast   mutedForeground on muted is 4.21:1; minimum 4.5:1 for text (WCAG 1.4.3).
neshel: wrote src/styles/neshel.generated.css (3 themes, 1 warning)

$ neshel validate
neshel: loaded neshel.config.ts
error   themes.dark.colors.primary   invalid-color   Expected a colour (#rgb, #rrggbb, rgb(), hsl(), oklch()); received "navy".
neshel: 1 error — nothing written.            (exit 1)
```

Diagnostics go to stderr; the final summary line goes to stdout. Paths in messages are
relative to the working directory. No colour codes when `NO_COLOR` is set or stdout is not a TTY.

## Recommended consumer scripts

```jsonc
"scripts": {
  "neshel": "neshel generate",
  "predev": "neshel generate",
  "prebuild": "neshel generate",
  "check:theme": "neshel generate --check --strict"
}
```

No `postinstall`/`prepare` hooks are used or recommended (FR-020).

## Negative test matrix (minimum)

| Case                                              | Expected                      |
| ------------------------------------------------- | ----------------------------- |
| No config                                         | exit 3, lists searched names  |
| Two configs                                       | exit 3, lists both            |
| Syntax error in TS config                         | exit 3, file + loader message |
| Config throws                                     | exit 3                        |
| No default export / default is a function         | exit 3                        |
| Unknown key / misspelled role                     | exit 1, path + suggestion     |
| Invalid colour, length, font stack, theme name    | exit 1, path                  |
| `version: 2`                                      | exit 1                        |
| Alpha colour on paired role                       | exit 1                        |
| Contrast failure, default mode                    | exit 0, warning               |
| Contrast failure, `--strict` / `contrast:"error"` | exit 1, nothing written       |
| `--check` stale / missing / fresh                 | exit 4 / 4 / 0                |
| `--out node_modules/x.css`, `--out x.txt`         | exit 2                        |
| Unknown option / command                          | exit 2                        |
| Unwritable output directory                       | exit 5                        |
| Paths with spaces and Unicode (all of the above)  | same behaviour                |
