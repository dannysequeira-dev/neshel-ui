# ADR 0007 — Configuration API boundary, colour processing and CLI loading

- Status: **Accepted** (2026-11-07, owner approval of milestone 002.0 with amendments B, C, D);
  implemented and CI-verified in feature 002 (see Verification)
- Date: 2026-11-07
- Feature: [002](../../specs/002-config-and-tokens/spec.md); normative detail in
  [contracts/config-api.md](../../specs/002-config-and-tokens/contracts/config-api.md) and
  [contracts/cli.md](../../specs/002-config-and-tokens/contracts/cli.md)
- Amends: `docs/package-contracts.md` (`cli` dependencies; validation location)

## Context

Consumers write `neshel.config.ts` with `defineConfig()`. Configuration must never be evaluated in
the browser; the browser entry must stay dependency-free; the CLI supports Node `>=22.13`, where
unflagged TypeScript type stripping is unavailable. The owner asked not to hand-write a colour
parser or colour-space conversion, to isolate colour dependencies from the browser-safe entry,
and noted that any exported subpath is public regardless of an "experimental" label.

## Decision

1. **`@neshel-ui/config` `.`** exports `defineConfig` (identity), public types and frozen contract
   data: `colorRoles`, `contrastPairs`, `defaults`. No runtime dependencies, no `node:` imports, no
   side effects, no subpath besides the stylesheets.
2. **No engine subpath.** Structural validation (hand-written), colour processing, resolution and
   CSS generation are private modules of `@neshel-ui/cli`.
3. **Colour processing** uses Color.js (`colorjs.io`, procedural `colorjs.io/fn`, only sRGB, HSL
   and OKLCH registered) behind one internal module, after a syntax allowlist (hex, `rgb[a]()`,
   `hsl[a]()`, `oklch()`). Alpha < 1 is rejected on every role except `border`; out-of-gamut colours
   warn and are gamut-mapped (CSS Color 4) for contrast only. Contrast is WCAG 2.1.
4. **Contrast policy**: built-in themes must pass (tests). Custom themes: effective policy is
   `error` with `--strict`, else config `contrast`, else `warn`.
5. **Loading** (D4): discovery in the working directory (`neshel.config.{ts,mts,js,mjs}`; ambiguity
   is an error); `jiti` loads the file in memory without cache files; the default export must be a
   plain object. Configuration files are executable, trusted project code; no sandbox is claimed.
6. **Dependencies of `@neshel-ui/cli`**: runtime `jiti`, `colorjs.io`; peer (and dev)
   `@neshel-ui/config` (`workspace:^`) so the CLI and the user's config share one contract copy.
7. **Shipped stylesheets** are generated by the CLI generator from `defaults` through a repository
   script and committed as `config` sources; a drift test guards them. `config` never imports `cli`.
8. **Output** (amendment D): explicit command only; path rules, rejection rules, byte-compare
   idempotence and temp-file + rename writes as specified in `contracts/cli.md`; exit codes 0–5.
9. **Tests** stay on `node:test`: repository tests before build, package tests against `dist`
   after build (`test:packages`), type fixtures through `tsc`.

## Consequences

- First inter-package dependency (`cli` peer → `config`); `check:pack` must accept public
  workspace peers and keep rejecting internal packages.
- `config` gains three data exports under semver (versioning policy in `contracts/config-api.md`).
- `cli` install grows by ~17.5 MB (Color.js 15.8 MB, jiti 1.7 MB unpacked; neither has
  dependencies); zero-config consumers and browser bundles are unaffected.
- `cli` and `config` must be released together while 0.x.

## Alternatives considered

- Engine subpath in `config`: public API surface and Color.js in a browser-adjacent package.
- Hand-written colour parser/converter: rejected by the owner (correctness risk).
- culori instead of Color.js: smaller (1.1 MB) but separate types and approximate gamut mapping;
  kept as the documented fallback behind the same internal module.
- Native type stripping: excludes Node 22.13 and non-erasable syntax.
- Schema libraries (`zod`, `valibot`): unnecessary for a small closed schema.

## Verification

- `check:pack`: `config` exports exactly `.`, `./tokens.css`, `./tailwind.css`, `./styles.css`; no
  runtime dependencies; relative imports only; `cli` dependencies exactly `jiti` + `colorjs.io`;
  `@neshel-ui/config` peer packed as a caret range; no install lifecycle scripts.
- CLI negative matrix (exit codes 1–5, every diagnostic code), jiti loading of TypeScript with
  non-erasable syntax without cache files, injected I/O failures and three byte-identical goldens,
  on Node 22, 24 and 26 (Linux) and Node 26 on Windows and macOS.
- The configured external consumer runs the packed `neshel generate` through its installed bin.
- A bundle importing only `defineConfig` is 272 bytes minified with no contract data (SC-006).
- Run IDs: `specs/002-config-and-tokens/evidence.md`.
